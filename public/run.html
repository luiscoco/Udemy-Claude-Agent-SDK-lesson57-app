01

Prerequisites

Use Node.js 24+, API credit and your selected model. Windows may need Git Bash. Docker Desktop with a Linux engine is required only for the Isolation case. Other cases run locally without Docker. No GitHub token, real secret fixture or attacker endpoint is needed.

node --version
npm --version
# For Isolation only:
docker version
02

Install and create the private .env

From presentations use the cd below. In a standalone clone skip that line. Preserve an existing .env or copy the template once, and enter your real model API key privately. The fake secret used in the attack lab is generated separately under a temporary fixture and never replaces your real .env.

cd .\agent-sdk\lesson57-prompt-injection
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
ANTHROPIC_API_KEY=your_api_key
CLAUDE_MODEL=claude-sonnet-4-6
PORT=3157
# CLAUDE_CODE_GIT_BASH_PATH=C:/Program Files/Git/bin/bash.exe
03

Start the web lab

Keep the terminal open and explore the five pages. Start with Clean, then Weak and the explicit boundary probes. The weak case is bounded by an outer fake-only fixture guard; it does not enable bypassPermissions or arbitrary shell/network access on your computer.

npm start
# http://127.0.0.1:3157
04

Verify the deterministic controls

Source tests check canonical paths, sibling prefixes, symlink escapes, fake-only loopback delivery, security graders and startup. They do not call the model or Docker.

npm test
05

Run real security cases

The model makes actual SDK calls. Weak may follow or resist the injection; inspect the observed result. Its trusted-host capability probe is labelled separately from model actions. Rules, Guard and dontAsk make explicit trusted probe requests so you can verify the controls even if the model ignores poisoned content.

npm run pipeline -- weak
npm run pipeline -- rules
npm run pipeline -- guard
npm run pipeline -- dontask
npm run pipeline -- hardened
npm run pipeline -- toolpoison
npm run eval
06

Build and verify the Docker boundary

Start Docker Desktop with its Linux engine and build the small probe image. Isolation uses a one-shot owned container with no network, read-only docs and root, no API key and fixed test code. The SDK controller stays on the host. The app removes only its named probe container afterward.

npm run docker:build
npm run pipeline -- isolation
